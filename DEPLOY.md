# Putting LayerForge online (Render + MongoDB Atlas + Razorpay)

About 30 minutes, all on free plans. You need three accounts: **MongoDB Atlas** (the database),
**Razorpay** (payments) and **Render** (runs the website). Do the steps in this order.

---

## 1. Database: MongoDB Atlas

Render does not keep files between restarts, so the shop's data (products, photos, users,
orders) lives in a hosted MongoDB database.

1. Sign up at <https://www.mongodb.com/cloud/atlas/register> and create a **free M0 cluster**.
   Pick the **Mumbai (ap-south-1)** region if offered.
2. **Database Access** → *Add New Database User*. Choose a username and let Atlas
   *autogenerate* a password. Copy it somewhere safe.
3. **Network Access** → *Add IP Address* → **Allow access from anywhere** (`0.0.0.0/0`).
   Render's free plan has no fixed IP address, so this is needed. The database is still
   protected by the username and password.
4. **Database** → *Connect* → *Drivers*. Copy the connection string. It looks like:

   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

   Put your password in place of `<password>`, and add the database name `layerforge`
   right after `.net/`:

   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/layerforge?retryWrites=true&w=majority
   ```

   This full line is your **MONGO_URI**. Treat it like a password.

## 2. Payments: Razorpay

1. Sign up at <https://dashboard.razorpay.com/signup>. You start in **Test Mode**: payments are
   pretend, nothing is charged, and you can use Razorpay's test cards and UPI ids.
2. **Account & Settings → API Keys → Generate Test Key.** You get a **Key ID**
   (`rzp_test_…`) and a **Key Secret**. The secret is shown only once; copy it now.
3. **Account & Settings → Payment capture**: make sure payments are captured
   **automatically** (this is the default for new accounts).
4. The webhook comes in step 4, after the site has an address.

To take real money later you finish Razorpay's KYC (business details and bank account), switch
the dashboard to **Live Mode**, generate **live** keys (`rzp_live_…`), and put those into Render
in place of the test keys. Nothing in the code changes.

## 3. Website: Render

1. Push this project to GitHub (it is already set up for
   `jangra-coder/Mern-sem3-ecommerce-website-Rahul`).
2. Sign up at <https://render.com> with your GitHub account.
3. **New → Blueprint**, pick the repository. Render reads `render.yaml` and shows one web
   service called `layerforge`.
4. It asks for the values marked `sync: false`:

   | Name | What to paste |
   | --- | --- |
   | `MONGO_URI` | the connection string from step 1 |
   | `RAZORPAY_KEY_ID` | `rzp_test_…` from step 2 |
   | `RAZORPAY_KEY_SECRET` | the key secret from step 2 |
   | `RAZORPAY_WEBHOOK_SECRET` | leave empty for now |

   `JWT_SECRET` is generated by Render automatically. Don't type your own.
5. **Apply.** The first build takes a few minutes. When it says *Live*, open the
   `https://layerforge-xxxx.onrender.com` address it shows. The sample products are added
   automatically on the first start.

> The free plan puts the site to sleep after 15 minutes without visitors. The first visit
> after that takes about a minute to wake it. A paid plan (from $7/month) stays awake.

## 4. Razorpay webhook (recommended)

If a customer pays and then closes the tab before they get back to the site, Razorpay tells
the shop directly through a webhook, so the order is still marked paid straight away. (Without
it, the shop still finds such payments by asking Razorpay every few minutes, but slower.) The
admin page shows a yellow warning until the webhook secret is set.

1. Razorpay dashboard → **Account & Settings → Webhooks → Add New Webhook**.
2. **Webhook URL:** `https://YOUR-SITE.onrender.com/api/payments/webhook`
3. **Secret:** make up a long random string (for example from a password manager) and keep it.
4. **Active events:** tick `payment.captured` and `order.paid`. Save.
5. In Render → your service → **Environment**, set `RAZORPAY_WEBHOOK_SECRET` to that same
   string and save. Render restarts the site.

Do this once in Test Mode and again in Live Mode when you go live (each mode has its own webhooks).

## 5. Make yourself the admin

Create a normal account on the live site first. Then, on your own computer, in the
`layerforge` folder, run (with your real connection string and email):

```bash
MONGO_URI="mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/layerforge?retryWrites=true&w=majority" npm run make-admin -- you@example.com
```

Log out and in again on the site; an **Admin** link appears in the account menu.

## 6. Try a test payment

With test keys, put something in the cart, choose **Pay online**, and use one of Razorpay's
test methods, for example UPI id `success@razorpay`, or the test cards listed at
<https://razorpay.com/docs/payments/payments/test-card-details/>. The order should show as
**Paid**. Cancel it from *My orders* and it should show as **Refunded** (a test refund).

## What protects the live site

- HTTPS everywhere; login cookies are HTTPS-only, `__Host-` locked, `HttpOnly` and `SameSite=Strict`.
- Passwords hashed with bcrypt. Wrong passwords are limited to 10 per email per 15 minutes
  (made-up emails behave the same, so this doesn't reveal who has an account). Changing the
  password logs out every other device, and the account page has "log out of all devices".
- Rate limits on log-in, sign-up, orders and the whole API.
- Every input is checked on the server; MongoDB operator injection is refused.
- Prices, delivery fee and totals are always calculated on the server.
- Payments: the Razorpay signature is checked with the key secret, then the shop asks Razorpay
  itself that the money was captured, for this order and the exact amount, before marking it
  paid. Webhooks are checked with the webhook secret. A payment that arrives for a cancelled
  order, or a second payment for the same order, is refunded automatically; refunds can never be
  sent twice, and an interrupted refund is finished automatically. The key secret never reaches
  the browser.
- Unpaid online orders are released after 30 minutes, but only after checking with Razorpay
  that they really weren't paid. Each account can have at most 3 unpaid and 5 not-yet-shipped
  orders, so nobody can hold all the stock.
- Photo uploads: admin-only, size-limited, and the real file type is checked (no SVG or scripts).
- Strict Content Security Policy: only the site's own scripts and Razorpay's checkout can run.

## If something goes wrong

- **Build fails on Render:** open the *Logs* tab; the last red lines say why.
- **"Could not connect to MongoDB":** check `MONGO_URI` (password, database name) and that
  Network Access allows `0.0.0.0/0`.
- **Online payment option is missing:** `RAZORPAY_KEY_ID` or `RAZORPAY_KEY_SECRET` is empty.
- **An order stays "Awaiting payment" after paying:** set up the webhook (step 4). The shop also
  checks with Razorpay before it releases any unpaid order, so a paid order is never cancelled
  by mistake.
- **A refund failed** (for example, not enough balance in a live Razorpay account): the admin
  page shows a red warning. Top up, then press *Retry refund* on the order.
- **Every login is refused with "Too many attempts" from many different people at once:**
  the limits count visitors by the address Cloudflare reports. Check the Render logs; if needed
  the limits can be raised in `server/src/app.js`.
